# コミュニケーション

- 日本語で応答する（コード・変数名は英語）。
- 簡潔に回答し、自明な説明は省略する。
- 複雑なタスクでは実装前に計画を提示し、承認後に着手する。

# コードスタイル

- 関数型アプローチを優先し、副作用を境界へ寄せる。
- 厳密な型付けを使い、application codeで`any`を使わず、外部入力は`unknown`から検証する。
- エラーは握りつぶさず、意味のある文脈を付けて処理する。
- 詳細な共通ルールは`~/.agents/rules/`にある。変更内容に関係するファイルだけを読む。

# Git

- Conventional Commits形式を使い、本文は日本語で書く。
- 確認なしにcommit・pushしない。
- unrelated changeを混ぜず、stage対象を明示する。

# 禁止事項

- README・ドキュメントを依頼なく生成・変更しない。
- テストコードを確認なしに削除・コメントアウトしない。
- 既存の動作するコードを理由なくrefactorしない。

# 秘密情報

- `.env`、`.env.*`、秘密鍵、credentialsファイルを読まない・表示しない・検索しない。
- 設定確認には`.env.example`、schema、変数名だけを使う。
- 秘密情報が誤って表示された場合は再掲せず、ローテーションを推奨する。

# Skills・Rules・Hooks

- 個人共通Skillの正本は`~/.agents/skills/`とする。
- 個人共通Ruleの正本は`~/.agents/rules/`とする。
- 個人共通Hookの処理本体は`~/.agents/hooks/`とし、登録は`~/.claude/`・`~/.codex/`で個別に行う。
- プロジェクト内の`AGENTS.md`、`.agents/`、各adapterがある場合は、プロジェクト側を追加適用する。

# AIDDボイラープレート適用リマインド

作業対象のディレクトリに`AGENTS.md`と`.agents/`が無い状態で、新規プロジェクトの立ち上げ・
初期実装・スキャフォールドを始めようとしていることに気づいたら、着手前に一度だけ次を案内する。

「AIDDボイラープレートを適用しますか？ `aidd apply` （technology profileがあれば `aidd apply --profile frontend`）」

- 使い捨ての検証・調査・一時ディレクトリでは案内しない。
- すでにボイラープレートが適用済み、またはユーザーが見送った場合は繰り返さない。
- 適用は既存ファイルを上書きしない。`aidd apply --dry-run`で内容だけ確認できる。

# ナレッジ蓄積リマインド

ユーザーが新しいツール・技術の検証、リリースノート確認、学びの共有を始めたら、セッション冒頭に一度だけ次を案内する。

「knowledge-vault パイプラインで記録しますか？ Amicalで話して `pbpasteの内容でログ更新して` で蓄積できます。」

すでにログ更新の指示がある場合は案内しない。

# 共有記憶

セッション開始時に`~/agents-share/AGENTS.md`を読み、そこに定義された順序に従う。
