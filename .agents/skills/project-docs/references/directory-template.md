# フォルダとページの雛形

この雛形は参照用で、絶対ではない。PJ に要らないフォルダは作らず、要るものは足す。番号は欠番のままでよい。

```
docs/
├── 目次.md                         生成。全ページの一覧
├── 01_仕様/
│   └── 仕様.md
├── 02_アーキテクチャ/
│   ├── システム構成.md
│   ├── <処理の流れ>.md              PJ の中心になる判定・処理の流れ（名前は PJ に合わせる）
│   └── 設計判断の記録.md            ADR
├── 03_データベース_<製品名>/         DB があるとき
│   ├── 仕組みと運用.md
│   ├── ER図.md
│   └── スキーマ表.md                生成（スキーマ定義から）
├── 04_セットアップ/
│   ├── 初期セットアップ.md
│   └── GitHub設定.md                外部サービスごとに 1 ページ
├── 05_運用マニュアル/
│   ├── コマンド一覧.md              生成（CLI 定義から）
│   ├── <日々の手順>.md
│   └── トラブル対処.md
├── 06_分析/                         分析・評価の方法
├── 07_検証記録/
│   └── YYYY-MM-DD_<題名>.md
├── 90_アーカイブ/                   役目を終えた資料
└── 閲覧用HTML/                      生成。md と同じフォルダ構成
```

## 各ページに書くこと

| ページ | 書くこと | 書かないこと |
|---|---|---|
| 仕様 | 目的、できること（使い方 × 入力 × 出力の表）、出力ファイルの形式、制約（外部サービスの上限など。推定なら推定と書く）、技術スタック、やらないこと | 実装の詳細、手順 |
| システム構成 | モジュール（ファイル）と役割の表、データの流れの図、外部サービスと認証の表、動く場所 | 分岐の細部（処理の流れへ） |
| 処理の流れ・判定ロジック | 入力から出力までの分岐、失敗したときに再試行・切り替え・停止のどれにするかの表、処理をまたいで引き継ぐ状態、止める条件、対象の決め方 | 設定値の一覧（セットアップへ） |
| 設計判断の記録 | ADR（状態・背景・判断・結果）。判断を変えたら古い ADR を「置き換え」にしてリンクする | 決まっていない案 |
| 初期セットアップ | 必要なもの、依存のインストール、秘密値の置き場所（変数名だけ）、環境変数の表、動作確認のコマンド | 秘密値の実値 |
| コマンド一覧 | 生成。サブコマンドとオプション | 手書きの説明 |
| トラブル対処 | 実際に出るメッセージごとに「何が起きているか」「どうするか」 | 起きたことのない仮定のエラー |
| 検証記録 | 日付・目的・条件・結果・分かったこと・次にやること | 正本の仕様（仕様へ反映する） |

## 実例での使い分け

### horse-racing-jev（データ収集・分析の CLI、DuckDB あり）

- `01_仕様` `02_アーキテクチャ` `03_データベース_DuckDB` `04_セットアップ` `05_運用マニュアル` `06_分析` `07_検証記録` `90_アーカイブ` をすべて使う。
- スキーマ表はテーブル定義から、コマンド一覧は CLI 定義から生成する。
- 検証記録はレースごとに `YYYY-MM-DD_レース名.md` で足していく。
- 手で描いた図の HTML（`06_分析/..._図解.html`）は、md から作らない静的ページとしてナビに載せる。

### YouTube文字起こし君（小さな CLI ＋ローカル Web 画面、DB なし）

- `01_仕様` `02_アーキテクチャ` `04_セットアップ` `05_運用マニュアル` だけを使う。`03`（DB なし）、`06`・`07`（検証を回さない）は作らず、番号は欠番のままにした。
- `02_アーキテクチャ/文字起こしの判定ロジック.md` が中心のページ。字幕と AI の分岐、再試行とモデル切り替えの表、巡回をまたいで引き継ぐ状態、止める条件を書いた。
- コマンド一覧は argparse の定義から生成する。

## README・AGENTS.md・memory との分担

| 置き場所 | 書くこと |
|---|---|
| README.md | 何のツールか、最短のセットアップと使い方、docs へのリンク |
| AGENTS.md | エージェントが最初に読む docs のページ（目次・仕様・設計判断）と作業ルール |
| `.agents/memory/` | 現在地・次にやること・未解決の課題。仕様と設計判断は docs が正本なので書かない |
| docs/ | 仕様・構成・判断・手順の正本 |
