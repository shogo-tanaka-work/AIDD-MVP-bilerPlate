# Project Docs

docs は、エージェントと人があとから読み返して判断できるようにするための正本である。
md を正本にし、目次・コマンド一覧・閲覧用 HTML のように導出できるものは生成する。

## 発動タイミング

- 新規プロジェクトで、仕様・構成・セットアップの資料を初めて用意するとき
- 平置きの docs（`docs/SPEC.md`・`docs/ARCH.md` など）を構成し直すとき
- 実装の変更で、仕様・処理の流れ・運用手順・設計判断が変わったとき
- 「後から振り返れるように」「HTML でも読みたい」と頼まれたとき

1 行の README 修正や、コードコメントだけで済む説明には使わない。

## 原則

1. **md が正本、HTML は派生物。** HTML・目次は生成し、手で編集しない。生成物が古ければテストか CI で落とす。
2. **コードが正本のものは、コードから生成する。** コマンド一覧（argparse・typer 等）や DB のスキーマ表は手で書き写さない。
3. **番号付きフォルダで分ける。** 読む順と役割が名前で分かるようにする（下の表）。PJ に要らないフォルダは作らず、番号は詰めずに欠番のままでよい。
4. **1 ページ 1 テーマ、冒頭に `確認日: YYYY-MM-DD` と関連ページへのリンク。** 確認日は内容を確かめ直した日で、更新のたびに直す。
5. **入口は短く、詳細は docs。** README・AGENTS.md・エージェントの memory は概要と docs へのリンクだけにし、同じ内容を二重に書かない。
6. **設計判断は ADR で残す。** 消さずに「置き換え」で更新し、背景・判断・結果を書く。
7. **経緯ではなく現在の正しい状態を書く。** 試行錯誤の履歴はコミットや検証記録へ。数値の根拠が推定なら推定と書く。

## フォルダの雛形（参照用。PJ に合わせて増減してよい）

| フォルダ | 置くもの | 目安 |
|---|---|---|
| `01_仕様/` | 仕様.md（目的・できること・入出力・制約・技術スタック・やらないこと） | 必須 |
| `02_アーキテクチャ/` | システム構成.md、処理の流れ・判定ロジック.md、設計判断の記録.md（ADR） | 必須 |
| `03_データベース/` | 仕組みと運用.md、ER図.md、スキーマ表.md（生成） | DB があるとき |
| `04_セットアップ/` | 初期セットアップ.md、GitHub設定.md など外部サービスの設定 | 必須 |
| `05_運用マニュアル/` | コマンド一覧.md（生成）、日々の手順、トラブル対処.md | 運用があるとき |
| `06_分析/` `07_検証記録/` | 分析方法、日付付きの検証・実験の記録（`YYYY-MM-DD_題名.md`） | 検証を回す PJ |
| `90_アーカイブ/` | 役目を終えた企画書など。消さずに移す | 必要になったら |
| `目次.md` | 全ページの一覧（生成）。エージェントの入口 | 必須 |
| `閲覧用HTML/` | md から生成した HTML（生成） | HTML が要るとき |

ファイル名は日本語で、内容が分かる名前にする（`仕様.md`、`文字起こしの判定ロジック.md`）。番号フォルダの外（`note/` など）は HTML の対象外の下書き置き場にしてよい。
各フォルダ・各ページの詳しい中身と実例は `references/directory-template.md`、ページの書き出しの雛形は `references/page-templates.md` にある。

## 進め方

### 新しく作るとき

1. コード・README・設定の雛形（`.env.example` 等）を読み、事実だけを集める。推測で埋めない。
2. 上の表から、この PJ に要るフォルダとページを決めてユーザーに示す。
3. 仕様 → システム構成 → 処理の流れ → 設計判断 → セットアップ → 運用の順に書く。処理の流れのページを最も厚くする。
4. 生成スクリプトを入れる（`references/html-generation.md`）。`make docs` などの入口と、生成物が最新かのテストを足す。
5. README・AGENTS.md を入口として短くし、docs へリンクする。
6. 生成し、HTML をデスクトップ幅とスマホ幅で開いて確かめる。

### 既存の docs を移すとき

- 旧ファイルは `git mv` で移し、履歴を残す。リンク・スクリプト・テンプレート・テストの参照を全部張り替える（`rg` で旧パスを探す）。
- 内容の書き換えと移動は、別のコミットに分ける。

### 実装を変えたとき

- 変更と同じコミットで、該当ページと確認日を直し、生成し直す。
- 判断を伴う変更なら ADR を足す。

## チェックリスト

- [ ] 目次.md と閲覧用HTML は生成物で、手で編集していない
- [ ] コマンド一覧・スキーマ表など、コードが正本のものは生成している
- [ ] 各ページに確認日と関連ページへのリンクがある
- [ ] README・AGENTS.md・memory に docs と同じ内容を書いていない
- [ ] 生成物が古いとテスト（または CI）が失敗する
- [ ] HTML は外部の CSS・JS を読まず、スマホ幅で横にはみ出さない
- [ ] 秘密値・個人情報・実在の接続先を docs に書いていない（変数名だけを書く）
